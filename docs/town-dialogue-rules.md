# ことほぎのまち：住民・会話・施設の条件

この文書は **現行の main の動作**と、その条件を編集する場所を整理したもの。
キャラクターの会話文や既読履歴を初期化する必要はない。新しいセーブ形式も作らない。

## 三つの責務

| 判断したいこと | 判定する場所 | データの出どころ |
| --- | --- | --- |
| 住民を迎えたか | `Progress.residents.owned` | ガチャ／保存データ |
| エリアが開いたか | `TownArea.isUnlocked` | 累計ことほぎ（`Progress.points`） |
| 住民のいまの居場所 | `residentCurrentArea` / `areaResidents` | CMSの `homeAreaId`、エリア開放、店番 |
| 会話相手が一緒にいるか | `TownRules.conversationPeers` | 上記の配置・会話を始めた画面 |
| どのセリフが有効か | `DialogueCatalog.select` / `DialogueCondition` | CMSの `dialogues.json` と `Progress` |
| 店を開放したか | `isMarcheOpen` / `isSalonUnlocked` | 本当の所有権・既読 |
| 屋台での接客セリフ | `selectMarcheDialogue` → `DialogueCatalog.selectById` | CMSセリフの固定ID、既読、屋台での会話回数 |

`TownRules` は **進行状況から計算した読み取り専用の窓口**。アプリの会話画面と広場描画から同じ規則を利用する。状態フラグを別途保存しない。

### 居場所の優先順位

1. `walkInTown=false`、または `homeAreaId=salon`：屋外には出ない。
2. とんこを取得済みで、開店セリフを既読：中央ひろばで店番（のんびり里には同時出現しない）。
3. それ以外：CMS登録の `homeAreaId` に住む。ただしエリア未開放なら中央ひろばに一時集合。
4. **デバッグ住民プレビューは例外**：本来のCMS登録エリアを表示するが、実際の住民取得や施設開放には影響しない。

※ 店番の **配置座標・足踏みアニメーション**は `lib/town.dart`。居場所の論理判定は `lib/town_areas.dart`。セリフの進行は別。

### 施設の開放

| 施設 | 条件 | 開店後 | デバッグ |
| --- | --- | --- | --- |
| 桜の美容室 | つやこをガチャで取得 | のんびり里から屋内画面に入れる | 強制開放／閉鎖のプレビューあり（本当の取得は変えない） |
| とんこの薬草茶房 | とんこを取得し、`041_pig_middle_033` を既読 | 中央ひろばに `marche.png` が出現。とんこが固定位置で店番 | 一時プレビューだけでは開店しない |

とんこの物語：`011`（ハーブを育てる）→ `012`（苗が枯れる）→ `021`（お茶をいれる）→ `022`（鉢植え）→ `032`（夢）→ `033`（開店）。`034` は屋台から話しかけたときの専用あいさつ（繰り返し可）。さらに屋台では、最初に `034`、次いで `035`〜`040`（初めての売上、試飲と購入、採算、値付け、リピーター）を一度ずつ順番に話す。すべて既読後は `041`〜`045` と `034` をローテーションする。開店条件の `033` と既存 `034` のID・`once`・`seenDialogue` を変えず、既読履歴を保存するので日付変更や再起動でも物語は巻き戻らない。

### セリフの有効条件（CMS）

- `mission`：ミッション累積回数。`withinDays: 1` は **達成当日だけ**。既読済みの `once: true` はもう出ない。
- `seenDialogue`：指定セリフが既読。物語の段階的な解放に使う。
- `townTogether`：会話画面から渡された参加者集合に話者・相手の両方がいること。**広場・公園など屋外の会話はそのエリアの住民だけ**。美容室の会話は屋内住民。住民一覧（roster）は従来どおり屋外住民の一覧を使うので、厳密な同じエリア判定ではない。
- `kotohogi`：累計ポイント。
- `date`：日本時間の日付・曜日・毎年の日付。
- 条件の組み合わせ：`logic: all`（AND）／`logic: any`（OR）。
- 条件を満たした中で優先度最大のセリフを選び、同点なら表示順をローテーション。
- **専用の施設会話**はランダム抽選を行わず、対象IDを明示して選ぶ。対象がない／相手が違う／条件未達ならエラーにする。屋台専用セリフ `034`〜`045` は通常の抽選に入らないよう優先度 `-1000` に設定し、`selectMarcheDialogue` が固定IDで一話ずつ選ぶ。不足・条件不一致のセリフに別IDを代用しない。日常会話の巡回番号だけはアプリ内メモリで管理し、再起動時に先頭から始まる。これは既存CMS形式の制約であり、将来は明示的な会話場所フィールドへ移行する余地がある。

### 編集するとき

- 名前・通常の住まい・スプライト：`assets/characters/characters.json`（CMSを使う）。
- 会話文・既読条件・掛け合い：`assets/dialogues/dialogues.json`（CMSを使う）。
- 施設開放トリガー（とんこ）：`lib/marche.dart`。開放条件を変えるなら物語IDの参照先も合わせてテストする。
- 住民の行き先・未開放エリア時の扱い：`lib/town_areas.dart`。
- 会話画面ごとの参加者の範囲：`lib/town_rules.dart`。
- 屋台の絵と店番位置：`lib/town.dart`。
- 美容室の取得条件：`lib/resident_collection.dart`。

変更したら `flutter analyze` と `flutter test`、CMSの `python -m unittest discover -s tools/dialogue_cms -p 'test_*.py'` を通す。特に開放前後、再起動後、デバッグプレビューでの居場所、屋台タップ、セリフの既読連鎖を確認すること。
