# ことほぎのまち：住民・会話・施設の条件

この文書は **現行の main の動作**と、その条件を編集する場所を整理したもの。
キャラクターの会話文や既読履歴を初期化する必要はない。新しいセーブ形式も作らない。

## 三つの責務

| 判断したいこと | 判定する場所 | データの出どころ |
| --- | --- | --- |
| 住民を迎えたか | `Progress.residents.owned` | ガチャ／保存データ |
| エリアが開いたか | `TownArea.isUnlocked` | CMSの `assets/town/areas.json` の `unlockAt` と累計ことほぎ（`Progress.points`） |
| 住民のいまの居場所 | `TownVisit` / `residentCurrentArea` / `areaResidents` | まちを開いたときのランダムなお出かけ先、エリア開放、店番 |
| 会話相手が一緒にいるか | `TownRules.conversationPeers` | 上記の配置・会話を始めた画面 |
| どのセリフが有効か | `DialogueCatalog.select` / `DialogueCondition` | CMSの `dialogues.json` と `Progress` |
| 店を開放したか | `isMarcheOpen` / `isSalonUnlocked` | 本当の所有権・既読 |
| 屋台での接客セリフ | `selectMarcheDialogue` → `DialogueCatalog.selectById` | CMSセリフの固定ID、既読、屋台での会話回数 |

`TownRules` は **進行状況と同じ `TownVisit` を見る会話・施設の窓口**。アプリの会話画面と広場描画は同じ行き先を利用する。配置や施設の状態フラグをセーブへ追加しない。

### 居場所の優先順位

1. `walkInTown=false`、または `homeAreaId=salon`（美容室所属）：屋外には出ない。
2. とんこを取得済みで、開店セリフを既読：中央ひろばで店番（のんびり里には同時出現しない）。
3. それ以外：所有する屋外住民を、実際に開放済みのエリアから等確率で1か所へ配置する。屋外の `homeAreaId` は互換性のためだけに保持し、通常の出現位置には使わない。
4. **デバッグ住民プレビューは例外**：古い保存互換フィールドに基づく位置に表示する（CMS上では居住エリアを編集できない）。実際の住民取得や施設開放には影響しない。

※ 店番の **配置座標・足踏みアニメーション**は `lib/town.dart`。居場所の論理判定は `lib/town_areas.dart`。セリフの進行は別。

### お出かけ先を決めるタイミング

- ホームや他のページから「みんなのまち」を開くと、新しい `TownVisit` を作る。現在のまちボタンを再度押しても引き直さない。
- 同じ滞在中は、エリア移動、画面の再描画、会話と既読の保存、日付更新、配信データの再読み込みでも既存住民の行き先を保つ。
- 滞在中に新しい住民を迎えた場合は、その住民の行き先だけを決める。新しいエリアが開いても、すでに配置済みの住民は移動せず、次のまち訪問で新しいエリアも抽選対象になる。
- とんこは開店条件が成立したら広場の店番を優先する。美容室の住民は引き続き屋内だけに登場する。
- 通常プレイでは**所持している住民だけ**をまちに表示する。未所持の配信キャラは、ローカルCMSのデータに含まれていても勝手に登場しない。
- デバッグメニューで「未所持の配信住民をお試し表示」を明示的にONにしたときだけ、一時訪問住民も同じ `TownVisit` でランダムに登場する。所持住民は重複せず、OFFに戻せばその場で消える。設定は起動中だけ保持され、ガチャ・セーブには影響しない。
- まちの描画と `townTogether` の判定には、同じ `TownVisit` を渡す。配置関数を呼ぶたびに抽選したり、会話側で別の配置を作ったりしない。
- 配置はメモリ内だけで保持し、再起動時は新しい訪問になる。不正な内部互換IDや、保持した行き先が未開放になった場合はエラーにし、別エリアへ自動で置き換えない。

このため、もぐたとおやすみくんは累計90以上でも、同じ開放済みエリアへお出かけしたときに掛け合いが成立する。毎回の同席や会話の当選を保証するものではない。

### 施設の開放

| 施設 | 条件 | 開店後 | デバッグ |
| --- | --- | --- | --- |
| 桜の美容室 | おしゃれさんをガチャで取得 | のんびり里から屋内画面に入れる | 強制開放／閉鎖のプレビューあり（本当の取得は変えない） |
| とんこの薬草茶房 | とんこを取得し、`041_pig_middle_033` を既読 | 中央ひろばに `marche.png` が出現。とんこが固定位置で店番 | 一時プレビューだけでは開店しない |

とんこの物語：`011`（ハーブを育てる）→ `012`（苗が枯れる）→ `021`（お茶をいれる）→ `022`（鉢植え）→ `032`（夢）→ `033`（開店）。`034` は屋台から話しかけたときの専用あいさつ（繰り返し可）。さらに屋台では、最初に `034`、次いで `035`〜`040`（初めての売上、試飲と購入、採算、値付け、リピーター）を一度ずつ順番に話す。すべて既読後は `041`〜`045` と `034` をローテーションする。開店条件の `033` と既存 `034` のID・`once`・`seenDialogue` を変えず、既読履歴を保存するので日付変更や再起動でも物語は巻き戻らない。

### セリフの有効条件（CMS）

CMS の「💬 セリフ管理」では、会話の種類別に絞り込み、各セリフの条件を日本語で確認できる。`seenDialogue` は前提と後続への移動ボタンから物語のつながりをたどれる。表示上の分類であり、Flutter の抽選・既読管理は変えない。ゆうぐれおやすみクラブは `/events` の別進行。


- `mission`：ミッション累積回数。`withinDays: 1` は **達成当日だけ**。既読済みの `once: true` はもう出ない。
- `seenDialogue`：指定セリフが既読。物語の段階的な解放に使う。
- `townTogether`：会話画面から渡された参加者集合に話者・相手の両方がいること。**広場・公園など屋外の会話はそのエリアの住民だけ**。美容室の会話は屋内住民。住民一覧（roster）は従来どおり屋外住民の一覧を使うので、厳密な同じエリア判定ではない。
- `kotohogi`：累計ポイント。
- `date`：日本時間の日付・曜日・毎年の日付。
- 条件の組み合わせ：`logic: all`（AND）／`logic: any`（OR）。
- 未読の `once: true` セリフを優先（その中で優先順位最大、同順位なら抽選）。ない場合は繰り返し可能な全候補を `1 + max(0, priority) ~/ 10` の重みで確率抽選。優先順位0も当選し、同じセリフが連続して出てもよい。
- **専用の施設会話**はランダム抽選を行わず、対象IDを明示して選ぶ。対象がない／相手が違う／条件未達ならエラーにする。屋台専用セリフ `034`〜`045` は優先度 `-1000` として通常抽選から明示的に除外し、`selectMarcheDialogue` が固定IDで一話ずつ選ぶ。不足・条件不一致のセリフに別IDを代用しない。屋台の物語終了後の日常会話だけは従来どおりアプリ内メモリの巡回番号で管理し、再起動時に先頭から始まる。一般住民の会話に巡回番号はない。

### 編集するとき

- 名前・スプライト・美容室所属：`assets/characters/characters.json`（CMSを使う）。一般住民の居住エリア編集UIは撤去。`homeAreaId` は旧カタログ／Dartの互換性のため保持し、`salon` だけを屋内所属の識別に使う。屋外出現先は開放済みエリアからランダムに決まる。
- エリア名・説明・開放しきい値：`assets/town/areas.json`（CMSを使う）。保存時に `lib/town_areas.dart` のエリアenum定義を同期する。ID・順番・背景パスと画像寸法はCMSでは編集不可。
- 会話文・既読条件・掛け合い：`assets/dialogues/dialogues.json`（CMSを使う）。
- 施設開放トリガー（とんこ）：`lib/marche.dart`。開放条件を変えるなら物語IDの参照先も合わせてテストする。
- 住民の行き先・開放済みエリアからの抽選：`lib/town_areas.dart`。訪問の作成は `lib/main.dart`。CMSの出現プレビューも同じ対象エリア・固定配置の規則を使い、「お出かけ先を決め直す」で別の配置例を確認する。
- 会話画面ごとの参加者の範囲：`lib/town_rules.dart`。
- 屋台の絵と店番位置：`lib/town.dart`。
- 美容室の取得条件：`lib/resident_collection.dart`。

変更したら `flutter analyze` と `flutter test`、CMSの `python -m unittest discover -s tools/dialogue_cms -p 'test_*.py'` と `node --test tools/dialogue_cms/test_town_visits.mjs` を通す。特に開放前後、再入場、エリア移動・会話中の配置保持、表示と掛け合いの一致、デバッグプレビューでの居場所、屋台タップ、セリフの既読連鎖を確認すること。

### おしゃべりさんとネイリストの親子お出かけ

母 `051_dog_aunt` と娘 `050_nailist` を両方お迎え済みで、ことほぎ商店街（累計180）が開放されていると、**新しくまちへ入るたびに25%の確率**で親子のお出かけが抽選される。`TownVisit.isFamilyOuting` の結果はその滞在中固定で、エリア移動や会話で再抽選しない。新しいセーブ項目はない。

当選した滞在中、母は通常のランダム配置には現れず、親子が商店街に並んで立つ。娘はその滞在中だけ美容室の室内表示からも外れる。商店街でいずれかをタップすると `051_dog_aunt_020/021` または `050_nailist_028/029` の親子専用掛け合いを2本ずつ交互に表示する（いずれも `townTogether` かつ優先度 `-1000`、通常抽選には混ぜない）。未当選時は今までどおりの居場所・セリフになる。デバッグの強制キャラ表示中はこの抽選を行わない。

※ かえるくんとの別れを確定させるストーリーはまだ未実装のため、本イベントは「ママ大好きな親子の普段のお出かけ」として実装し、別れイベントの既読条件とはまだ連動しない。

### おやすみクラブ完了と、言葉にしない別れ

ネイリストとカエルくんの間に別れ話イベントは置かない。ゆうぐれおやすみクラブの第三段階「joining」の導入を最後まで読み、既存の `Progress.oyasumi.completed == 3` に到達した時点で、二人はすでに恋人ではないものとして扱う。別れのセリフ・確認画面・追加の既読フラグは作らない。

CMS の `oyasumiClub` 条件 `{"type":"oyasumiClub","completed":false}` をカエルくんの `029_office_worker_002` （「つきあってるんだ」）に設定済み。完了後は通常抽選の候補から消える。条件の真偽は既存保存データから導くため、途中まで遊んだユーザーの保存もそのまま使える。親子のお出かけは交際時代から楽しめるので、クラブ完了とは無関係に発生する。
