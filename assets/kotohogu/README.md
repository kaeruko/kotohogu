# Kotohogu UI parts

ユーザー指定の `Downloads/tmp/kotohogu_ui_parts/ui_parts` から、原本を変更せずコピーしたUI素材です。

- `09_nav_home.png`: ホームのナビゲーション
- `11_nav_town.png`: まちのナビゲーションとリンク
- `12_nav_history.png`: 履歴のナビゲーション
- `24_badge_clear.png`: 達成済みバッジ
- `31_dialogue_box.png`: ハルのホームメッセージ枠
- `32_heart_red_1.png`: 社会貢献ポイントのアイコン
- `10_nav_quest.png`: 本日のミッションへの看板
- `town_background.png`: ユーザーが追加した `862717e4-2169-43ea-a131-7e35b12b2d6e.png` のコピー。ホームの全面背景

文字・ポイント・ミッションの状態・ボタンはFlutter側で描画します。素材内の固定レベル、通貨、スタミナ、固定達成数をアプリの状態として表示しないため、それらを含む素材は採用していません。

## エリア別の背景サイズ

背景画像はすべて同じピクセル寸法である必要はありません。
`town_background_001.jpg`（中央ひろば）は768×1376、`park_background_001.png`（ふれあい公園）は937×1679、`street_background_001.png`（商店街）は937×1679、`village_background_001.png`（のんびり里）は941×1672です。
`lib/town_areas.dart` の背景パスと原寸（幅・高さ）を組にして登録し、Flutterではその原寸のキャンバスごと `BoxFit.cover` で表示します。背景と住民の歩行座標が同じ変換を受けるため、縦横比が異なる画像でも住民だけずれることはありません。登録寸法が実際の素材と異なる場合は `test/town_areas_test.dart` が失敗します。ふれあい公園は累計90ことほぎで開放され、背景の上を住民が歩けます。

## 桜の美容室（のんびり里の玄関）

- のんびり里の右手前、青いのれんがある家の玄関をタップすると「桜の美容室」に入れます。おしゃれさんをお迎えして入れる状態になると、玄関の少し左上に「✂ 桜の美容室／入口はこちら ↘」の目印が現れ、目印からも入れます。未開放では目印は出ません（デバッグ強制開放・強制未開放も反映）。
- 画面左上の「里山にもどる」または端末の戻る操作で、選択中の里山に戻ります。
- 内装画像は `assets/kotohogu/salon_background_001.jpg`（941×1672）を使用します。画像が未追加の場合は Flutter の通常のアセット読み込みエラーとして停止し、別画像に自動切替しません。
- 玄関の判定座標は `lib/town.dart` の `villageSalonDoor` で、背景の原寸を基準にするため `BoxFit.cover` での拡縮・トリミングに追従します。
- 美容室はCMSで住むエリアとして選択できます（屋外の5番目のエリアではありません）。ガチャでおしゃれさん（オーナー）をお迎えすると入口が開放されます。おししょうさん（旧きものぎつね）は公民館のお花教室に登場するため、美容室の配置一覧には含めません。開放後、室内にはお迎え済みの住民が登場します。室内ではその場で動き、タップするとCMS管理のセリフを話します。美容室へ配置変更した住民は屋外の歩行一覧には登場しません。室内は最大7人です。

## ことほぎ公民館（ことほぎ商店街から入る施設）

- 累計240ことほぎで公民館が開放されます。商店街の「公民館へ」ボタンから入れます。未開放ではボタンは表示されません。ことほぎ残高ではなく累計獲得ポイントで判定します。
- 室内背景は `assets/kotohogu/community_center_background_001.png`（941×1672）。左側のお花教室に「おししょうさん」（`031_kimono_fox`）、右側の体操教室に「コーチ」（`037_tora`）を配置します。
- 公民館は公共施設なので、開放後は2人ともガチャの所持状態に関係なく登場して会話できます。戻るボタンで商店街へ戻ります。
- `http://127.0.0.1:8765/facilities` の配置CMSから、公民館の住民の位置と共通サイズを調整できます。住民の位置は背景画像の原寸座標です。

## びょういん（診療所）

- せんせい（`004_neko`）をガチャで迎えると、累計ことほぎ数に関係なくびょういんが開院します。ナースさん（`024_nurse`）は取得してから診療所に登場します。せんせいを未所持の間はナースさんだけで開院しません。
- 背景は `assets/kotohogu/hospital_background_001.png`（941×1672）。診療所は独立したまちエリアですが、キャラの初期位置と共通サイズは他の施設と同じ `assets/facilities/rooms.json` で管理します。
- `http://127.0.0.1:8765/facilities` の「びょういん（診療所）」から、せんせいとナースさんの位置・サイズを編集できます。編集結果は `lib/facility_config.g.dart` に生成され、ゲームの描画にも適用されます。変更後はアプリを再ビルドしてください。
- 診療所の登場人物は現状この2人に固定です。所持条件を維持するため、CMSから別のキャラを追加したり2人を削除したりすると保存時にエラーになります。

## 美容室のデバッグ開放テスト

開発版では、メニューの「施設の開放テスト」から「通常の開放条件で判定」「強制開放してテスト」「強制未開放でテスト」を切り替えられます。強制開放中は里山が未開放でも入口を試せ、おしゃれさんなど、美容室に配置された住民を未所持でも室内で仮表示できます。強制未開放ではオーナーを所持していても入れません。ガチャ所持状況と既読セリフは書き換えず、アプリを再起動すると通常判定に戻ります。製品版では常に通常判定です。

## エリアに登場する住民の人数

屋外の住民はCMSの居住エリアが開放されるまでは中央ひろばに仮住まいし、累計90・180・300ことほぎで元のエリアが開放されると自動で引っ越します。所持住民と保存データは変更せず、1エリア・まち全体とも「最大8人」の制限はありません。美容室の住民は室内専用で仮住まいの対象外です。デバッグで住民を選択した場合は開放状況にかかわらず元の居住エリアをプレビューします。
ひとつのエリアで9人以上になったときは、歩行位置と表示サイズを人数に合わせて割り振ります。
デバッグ住民選択も人数制限なし、ホームの住民列は横スクロールで全員表示します。
なお、拍手演出の同時表示は別の仕様として従来どおり最大8人です。
公園の背景 `park_background_001.png` は937×1679ピクセルです。

## 公園の歩行・お気に入りスポット

`lib/town_walk.dart` の `parkResidentRoutes` は、新しい遊具・ベンチのある公園背景を想定した背景比率の座標です。立ち位置は描画時に住民画像の足元を基準に決まります。

- うさぎ：すべり台のそば
- りす：花壇と案内板のそば
- やすぞう：水飲み場の近く
- おやすみくん：手前右側のベンチのそば（待機）
- コーチ：ブランコのそば

それぞれの周辺を小さく散歩します（おやすみくんは待機）。未指定の住民や配信テスト住民も、中央の通路上の予備ルートを使います。既存の他エリアの散歩処理、所持状態、セーブデータ、会話条件には変更を加えません。

**背景素材について:** 本リポジトリにある現行の `park_background_001.png` は旧背景です。遊具付きの新背景へ差し替える際は、素材そのものをリポジトリへ追加した上で `TownArea.park` の背景パスとソース寸法を更新してください（元画像は 768×1376）。公園のルート座標は比率で保持するため、画像サイズが変わっても同じ相対位置を指します。画像が存在しないときに別背景へ自動的に切り替える処理はありません。
